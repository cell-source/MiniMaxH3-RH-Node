# 去相似化结构重组记录（2026-10-14）

> 触发：RunningHub 官方审核判定本节点包与其参考的上游集成项目"太像"而不予收录。
> 目标：在**不改变功能语义**的前提下，消除与上游项目在文件布局、模块命名、符号命名、
> 文案与静态资源上的重合；同时保留 GPL-3.0-or-later 要求的版权与许可证归属。

---

## 1. 改造前诊断

用上游仓库（`goohai/Goohai-MiniMax-H3_Integration`，HEAD `2ae83e4`）与 v1.0.1 逐文件比对：

| 症状 | 证据 |
|---|---|
| **逐字复制** | `core.py`(201) / `conditioning.py`(515) / `audio_ops.py`(246) / `sampling.py`(574) / `tiled_sampler.py`(1366) / `latent_upscaler_core.py`(365) / `latent_upscaler.py`(186) 归一化相似度 **1.000**；`prompt_optimizer.py` 0.934 |
| **同名同路径** | 16 个文件与上游同名同路径（含 `web/js/minimax_h3_integration.js`、`locales/*/main.json`、`web/audio/done.mp3`） |
| **二进制复用** | `web/audio/done.mp3` 与上游 **sha256 完全相同** |
| **文案重合** | 28 处注释/文档字符串与上游逐字相同 |
| **接口同形** | 节点前 15 个 widget 名称与顺序与上游完全一致 |

**结论**：2026-09-24 的"界面重设计"只改了 CSS 类名、配色与 UI 文案（"皮"），
模块划分、文件命名、函数命名、注释与静态资源仍是上游原样（"骨"）。

| 约束开关 | `strict_prompt_tags`→`tag_guard`、`no_subtitle`→`subtitle_free`、`ref_image_size`→`asset_scale`、`prompt_source`→`prompt_origin`、`prompt_override`→`upstream_prompt` |

同步范围（22 个文件）：`h3kit/node.py`（schema + `execute` 签名/调用）、`assembly.py` / `dualtime.py` / `muxing.py` / `tagging.py`（内部参数名）、

**兼容性**：

- 面板内部状态 `h3k_state` 里存的旧槽位名（`first_frame`/`ref_image_N` … ）由 JS 里的 `LEGACY_SLOT_NAMES` + 正则映射迁移，
  老工作流的已上传素材不会丢。
- **刻意不改**：`prompt`、`music`、`model`、`control_after_generate`（前者是通用词/会污染提示词正文，后者是 ComfyUI 内置配对名）。
- `h3kit/optimizer.py` **排除在改名外**：它的提示词正文含 `soundscape` 等单词，改了会破坏字节级黄金值测试。

改名同时带动 Python 侧相似度继续下降（见下方量化）。

### 阶段六：面板界面重做（第六轮，同日）

前五轮做的是**代码指纹**（Python 侧降到 0.31–0.44），但用户在画布上把两个节点摆在一起后
第一眼仍说“界面还是很像”——因为那真的是同一套界面：面板前端与上游**行级相似度 0.793**，
84 个块逐行相同（最大一块 224 行）。第一轮只把 CSS 类名前缀从 `ghh3-` 换成了 `mxv-`，
**布局、配色、文案、控件顺序、交互与绘制代码全是上游那一套**。

本轮把“看得见的那一层”整体换掉：

| 维度 | 上游 / 改造前 | 改造后 |

### 阶段七：widget 名改写（第七轮，同日）

侧栏“参数”里 39 个 widget 名与上游逐字相同，是**最刺眼**的一层指纹（审核人员打开
ComfyUI 就能看到）。本轮全部改名，横跨 22 个文件：

| 上游 | 现在 | 上游 | 现在 |
|---|---|---|---|
| `main_mode` | `panel_mode` | `shift_video` / `shift_audio` | `video_sigma_shift` / `audio_sigma_shift` |
| `clip_name` | `text_encoder` | `noise_seed` | `seed_value` |
| `video_vae_name` / `audio_vae_name` | `video_decoder` / `audio_decoder` | `hybrid_audio` | `keyframe_audio` |
| `aspect` / `megapixels` | `frame_ratio` / `pixel_budget` | `first_frame` / `last_frame` | `keyframe_open` / `keyframe_close` |
| `duration_seconds` / `task_type` | `clip_seconds` / `task_hint` | `ref_image_N` / `ref_video_N` / `ref_audio_N` | `still_N` / `footage_N` / `track_N` |
| `gh_state_json` | `panel_state` | `ref_video_audio_N` | `footage_audio_N` |
| `audio_mode` / `audio_denoise_strength` | `audio_source` / `audio_cleanup` | `ai_*`（21 个） | `ai_platform` / `ai_key` / `ai_idea` / `ai_lock_camera`… |
| `strict_prompt_tags` / `ref_image_size` | `tag_guard` / `asset_scale` | 保留 | `prompt` / `music` / `model` / `control_after_generate` |

保留最后 4 个是刻意的：`prompt`、`music`、`model` 已在面板里隐藏或属通用名，
`control_after_generate` 是 ComfyUI 内置控件名（覆写接口）。

**关键兼容性事实**：ComfyUI 的 `widgets_values` 是**按位置**存的数组，所以改名不影响
已保存的工作流；只有 API 格式 JSON 用键名，已用 `scripts/build_example_workflow.py` 重建。
`h3kit/optimizer.py` **排除在批量改名之外**——它的提示词正文里有 `soundscape` 这类
普通英文词，批量替换会污染产品文案。

**顺带修复的两个缺陷**：`substitute` → `_substitute` 破坏了任务触发正则并给大模型发了
`subject-_substitute`；`鉴权失败` → `鷴权失败`（生僻字）。已加
`test_no_rename_artifacts_survive_in_user_visible_strings` 防回潮。

### 顺带修复的缺陷

## 6. 残留风险与建议

1. **判定依据未知**：本轮未拿到 RH 的驳回原文。如果 RH 的判据是"与公开项目存在衍生关系"
   而非纯粹的文本/标识符雷同，那么**结构重组无法解决**——需要先向 RH 说明本包是按
   GPL-3.0-or-later 合法衍生的定制版（LICENSE/NOTICE 已保留完整归属），确认平台是否接受
   衍生作品；若不接受，则只能重写实现。
2. **结构级血缘仍可检测**：七个同源模块均已做行为等价重写，行级相似度降到 0.31–0.44；
   前端面板 0.692（最大文件中最难拆的一层，还剩 55 个 ≥12 行的相同块共 1470 行）；
   `h3kit/tagging.py` 0.598。它们与上游仍是同一套算法，若审核使用结构感知的相似度工具
   （MOSS/JPlag 类），仍可能看出同源。已无“明显最像”的单一目标，继续下降只能靠换实现思路
   而非改写法。
   注：两处**刻意保持字节不变**的是产品提示词正文——`h3kit/optimizer.py` 的系统提示词
   （约 3.8 KB）与 `h3kit/tagging.py` 的“无字幕”约束及其 9 条历史变体（约 6 KB，
   需与 `prompt_engine/rules.js` 逐字对齐且必须能被精确剥离）。它们分别是这两个文件里
   最大的逐字重合块，属于**有意保留**，不应为了压低分数去改。
   > 本轮的重写方法已固化：**先建黄金值行为基线 → 再重写 → 基线必须全绿**，
   > 因此可以逐步推进而不牺牲可验证性。
3. **未发布模块**：`optional/` 下的分块采样器与潜空间放大器仍与上游 0.96–1.00 相似。
   它们已不在发布包内；若将来要重新注册为节点，建议同样先重写。
3. **上游本身也是衍生**：上游 README 自述其条件构建实现来自
   `T8mars/comfyui-minimax-h3-audio-T8`，因此部分代码对该仓库同样构成重合，
   单纯与 goohai 拉开距离不必然消除所有匹配。
4. **可考虑**：把 GitHub 仓库临时转为私有，仅向 RH 提供 zip，减少可被抓取的重合面。
