# MiniMax H3 提示词生成器 — 技术文档

> 最后更新：2026-08-20  
> 规范基线：MiniMax 官方仓库 `MiniMax-AI/MiniMax-H3` 中的 `skills/h3-prompt-writing/`。

## 1. 项目定位

这是一个单文件、零构建依赖的 HTML 工具，把普通提示词翻译、整理或扩写为 MiniMax H3 提示词。

- 核心文件：`MiniMax-H3-提示词生成器.html`
- 官方本地规范：`skills/h3-prompt-writing/SKILL.md`
- 基础/关键帧规范：`skills/h3-prompt-writing/references/base-en.txt`
- 全参考规范：`skills/h3-prompt-writing/references/ref-en.txt`
- **版本号自动升级策略（无需手动维护）**：`APP_VERSION` 仅作基线（如 `1.0`）；语义版本自动递增——页面检测到文件修改时间变化时，自动 `V1.0 → V1.1 → V1.2 ...`（`1.9` 后进位 `2.0`），记录存于 localStorage；build 号由文件最后修改时间生成（`YYYYMMDD-HHMM`），每次保存自动递增。合并显示为 `v1.2 · build 20260820-1606`。注意：换浏览器/清浏览器数据会回到基线（单文件离线工具的正常代价）；人工校准可在控制台执行 `localStorage.removeItem('h3-app-version')` 后刷新。

发生冲突时，以上 MiniMax 官方文件优先；HTML、页面指南和本文档必须同步更新，不允许再定义一套产品私有格式。

## 2. 五种模式与官方输出契约

| 模式 | 含义 | 官方格式 |
|---|---|---|
| `t2va` | 纯文本生成视频 | 三核心字段，无对齐指令 |
| `i2va` | 首帧图生视频 | 官方首帧对齐指令 + 三核心字段 |
| `fl2va` | 首尾帧图生视频 | 官方首尾帧对齐指令 + 三核心字段 |
| `l2va` | 尾帧图生视频 | 官方尾帧对齐指令 + 三核心字段 |
| `ref2va` | 图片/视频/音频全参考 | 六 section |

普通文本输入默认使用 T2VA。I2VA、FL2VA、L2VA 和 Ref2VA 的提示词会引用实际提交给 H3 的参考素材；本工具只生成提示词文本，不上传素材。

## 3. 基础模式格式

T2VA 直接输出三个核心字段：

```text
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

I2VA 在三字段之前添加：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

FL2VA 在三字段之前添加：

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

L2VA 在三字段之前添加：

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

`N` 必须是实际最后一个镜头编号；`S.SS` 必须等于视频时长并保留两位小数。

「语言」选「中文」时，三条指令行使用中文版（`Picture N`/`Shot N`/`[Shot N]`/时刻数字等技术 token 保持英文，其余为中文、全角标点）：

```text
对于目标视频，在目标视频的第 0.00 秒，<Picture 1>（来自 [Shot 1]）被完整引用。
参考图片与目标视频的对齐关系——Picture 1（来自 Shot 1）对齐目标视频的 0.00 秒处；Picture 2（来自 Shot N）对齐目标视频的 S.SS 秒处。
参考图片与目标视频的对齐关系——<Picture 1>（来自 [Shot N]）对齐目标视频的 S.SS 秒处。
```

生成器按语言输出对应版本并按同一语言校验（`i2vaAlignLine/fl2vaAlignLine/l2vaAlignLine` 生成、`i2vaAlignOk/fl2vaAlignMatch/l2vaAlignMatch` 校验）；`normalizeKeyframeAlignment` 重建首行时同样使用当前语言版本。切换语言后旧输出的首行会在下一次生成/重建时更新为对应语言。

全局硬约束：视频时长必须为 2–15 秒整数（官方为 4–15，2–3 秒为非官方扩展）；最终提示词不得超过 7000 字符。任一条件不满足时，结果会保留供修改；复制和下载均不拦截，页面只显示中性结果提示，具体校验原因写入浏览器控制台供内部调试。Ref2VA 上游虽建议 `detailed_description` 为 350–500 个英文词，但本工具的“受限扩写”优先围绕既有语义展开，不要求达到最低词数，也不得为凑字数新增人物、事件、新动作或对白。

## 4. Ref2VA 六 section

固定顺序如下：

```text
subject_definitions:
...

summary:
[reference generation] ...

retention_analysis:
...

detailed_description:
The target video uses ...
[Shot 1] ...

overall_soundscape:
...

non_diegetic_music:
...
```

引用标签包括 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`。标签必须先定义再使用，并在全部 section 中保持一致。

### 替换类任务强化规则（2026-09-02 实测教训）

用参考素材中的人物/物体替换源视频中的某元素（输入含「替换/换成/替代/replace/swap/substitute」等语义）时，AI 在线生成的 Ref2VA 模式指令会自动注入替换类强化规则（源码常量 `REF2VA_REPLACE_INSTR`，触发正则 `REF2VA_REPLACE_RE`）：

- `subject_definitions` 至少三行：替换来源 `<Subject N>`（写明要继承的脸型五官、发型、体型、服装）、被替换角色或被保留整体内容 `<Subject M>`（若定义被替换角色，写明其作用只是动作与节奏模板——身体动作、姿态、转头、面部微动作与时机原样保留，其外貌不再出现在目标视频中；若是保留内容则逐项列出场景环境、构图、镜头运动、其余人物）、以及单独一行的 `<Video N> is the source video for the target video edit.`；`<Picture N>` 首选只出现在 `<Subject N>` 定义句中作为来源；不允许只用一句 "used to replace" 带过替换用途。
- `summary` 任务前缀后先写 `The target video is an edited version of <Video N>.`，再明确替换关系与「外貌全帧一致 + 完整执行原角色全部动作」；只引用 `<Subject N>` / `<Subject M>` / `<Video N>`。
- `retention_analysis`：替换来源用 `attribute_transfer`（直接写继承哪些特征 + 执行原角色整套身体动作、姿态、转头与面部微动作，节奏与时机与源视频严格一致），不得写成「外貌转移到被替换者身体上」；动作模板或保留内容用 `fully_preserved`（动作模板注明「仅保留动作、姿态与时机并由替换来源执行，其外貌不再出现」）；`<Video N>` 写一行结构保留（如 `(source structure): fully_preserved - 仅替换角色，镜头结构与节奏保留`）。
- `detailed_description` 以替换动作为正文核心，全部用肯定语气描述全片实际发生什么；`[Shot 1]` 之前写一句继承源视频光线色调的风格句；明确替换与外貌一致性贯穿全片每一帧、绝不能只替换首帧；固定镜头与画面稳定约束各最多一句并放在替换描述之后，避免大段否定句把替换指令淹没。
- 标签自检：summary、retention_analysis、detailed_description 中出现的每个标签都必须能在 `subject_definitions` 中找到（独立定义行或定义句内的来源引用，`validateRefLabels` 按此从宽判定）；独立定义的每个标签都必须在 `retention_analysis` 有对应行。
- 规则来源：实测失败案例（单 Subject 定义 + 一句带过替换 + 大段「不得改变」否定句）导致 H3 只替换首帧；对照成功的豆包提示词采用上述「多主体 + 肯定语气 + 全帧一致」写法。

## 5. 对白、语言与镜头

- 所有描述正文使用「语言」选项所选语言。
- AI 模式下，「语言」选项三选一：选「中文」时正文与对白均为中文（非官方扩展，官方期望英文提示词）；选「English」时正文与对白均为英文；选「English 正文 + 对白原文」时正文为英文，对白逐字保留原始语言、措辞和标点，不翻译不改写（官方默认行为）。
- 歌词和画面内可见文字默认保持原始语言。
- 所有模式的发声者都使用稳定 `(S1)`、`(S2)` ID。
- Ref2VA 中被引用主体发声写作 `<Subject N> (Sx)`。
- 所有模式的对白统一写作 `<d>[Chinese] 台词</d>` 或 `<d>[English] 台词</d>`：统一语言模式下标签与「语言」选项一致、不得混用；「English 正文 + 对白原文」模式下标签按每句实际语言选择，标签与台词语言不匹配即校验拒绝（[English] 标签内残留中文同样拒绝）。
- **格式类型明确分流**：关闭开关时标识为“官方严格格式”，对白使用 `<d>[语言] 台词</d>`；默认开启时标识为“抗残音实验格式”，针对 H3 已知 bug（GitHub issue #50/#51）把对白改写为内联 `[语言] 台词`。实验格式有意偏离官方 `<d>` 契约，页面结果区必须持续显示该差异。音景/配乐严格以勾选项为准。
- `<d>` 内只放语言标签和台词（台词与正文同语言）；说话人、语气与动作放在外面。
- `[Shot 1]` 不带时间戳。
- 后续镜头使用 `[Shot N] At MM:SS.mmm`，编号连续、时间严格递增且小于总时长。
- “AI精细时间戳”默认启用且只作用于 AI 在线生成。固定镜头开启时，各模式沿用唯一 `[Shot 1]` 的连续动作时间段；取消固定镜头后，T2VA、I2VA、L2VA 与 Ref2VA 沿用原有官方多镜头切点规则，仅在内容确实需要多个镜头时为后续 `[Shot N]` 添加 `At MM:SS.mmm`。FL2VA 首尾帧是定向增强的例外：取消固定镜头且启用自动时间戳时仍保持唯一 `[Shot 1]`，使用 `0.0-0.5s:`、`0.5-1.5s:` 等至少两个连续区间完整覆盖总时长；禁止空冒号、单个全时长粗略区间、多 Shot 或 `At` 切点。首次 FL2VA 输出缺失、单段、不连续或越界时，生成流程携带具体错误最多自动纠正两次。该增强不作用于其他模式、固定镜头分支、手工生成或离线生成。任何路径都不得为了凑时间点新增动作、物体、事件、反应、结果或对白。
- 切换固定镜头、无字幕约束或画面稳定选项时，会直接对当前输出增删对应的确定性约束，不重新生成或覆盖已有 AI 正文；AI精细时间戳关闭后保留已有合法时间戳，因为无法可靠区分用户原有切点与 AI 添加切点。独立 `timeline:` 字段或声音字段之后的动作时间段属于确定性结构错误；疑似重复对白和过粗动作时间段只提供非阻断提醒，不自动删改台词或动作语义。长对白所在时间段不受通常 2 秒上限限制。若打开固定镜头后当前结果仍为多镜头，保留正文并给出中性人工核对提醒，不擅自合并镜头。抗残音开启时对当前结果就地去除 `<d>` 包装，并要求每句内联对白独占一行、在行尾结束；关闭时依据该边界契约自动恢复 `<d>[语言] 台词</d>` 官方包装，不重新生成或覆盖其他正文。
- 音景与配乐选项在五种模式的手工、离线和 AI 回填路径中使用同一契约：关闭后对应字段立即写为 `N/A`，开启后使用输入框已有内容，内容为空时填入确定性的合规默认描述。抗残音、自动时间戳、固定镜头、无字幕约束和画面稳定五个功能选项均保存于本机；刷新页面及“功能全选/全不选”后状态保持一致。
- **无字幕约束 v4**（2026-09-23，默认启用）：在主描述 `[Shot 1]` 后按语言注入七句完整约束，强调①从首帧到末帧的干净画面母版；②对白引文、语言标签、说话人编号仅指导声轨；③画外音归属和画内嘴部状态保持原意；④每句台词及前后停顿中，画面下部、边缘和四角连续呈现场景；⑤画面按已有动作发展，与台词措辞和节奏解耦；⑥仅保留输入明确设定的实体文字；⑦声轨与画面分通道。保留已有构图和物体，不为占位新增道具。整块只注入一次，AI 不得缩写；开启、关闭、切语言及回填时兼容剥离 v3 中英文块。英文常量与实验脚本逐字一致。约束块不计入扩写额度，但仍计入 7000 字符总上限。当前仅完成程序验证，未进行 v4 视频生成效果验证。
- **AI 输出语言硬约束**（2026-09-23 改版：「语言」选项三选一——中文 / English / English 正文 + 对白原文；原 2026-09-20 英文硬约束保留为英文正文模式语义）：中文 / English 为统一语言模式，正文与对白同语言；「English 正文 + 对白原文」为官方默认组合，正文英文、对白逐字保留原语言，标签按每句实际语言选择 [Chinese]/[English]。英文正文模式（en 与 mixed）：除对白标签外不得出现任何中文（含双引号内）；zh 模式：剥离六个固定约束、对白及结构 token 后，逐字段、逐行拒绝纯英文自然语言描述；允许中文中的英文专名，不作为完整语种识别器。**语言全局化（2026-09-23）**：zh 模式下固定镜头/画面稳定/无字幕三条约束句注入中文版（双语常量并存，剥离时两版都移除，注入/校验按当前语言），动作时间段用中文格式 `0.0-1.5 秒：`（校验正则同时识别 s 与 秒 两种单位，全/半角冒号），固定镜头禁令用中文运动词组合（避免单字误伤“不推拉摇移”类否定描述）；**Ref2VA 六 section 内容语言跟随「语言」选项**：zh 模式下 subject_definitions 定义句用中文（如 `<Subject 1>：<Picture 1> 左侧坐着的…` 或 `<Subject 1> 是 <Picture 1> 中的…`）、summary 前缀后的正文用中文、retention_analysis 破折号后的说明用中文（标记 fully_preserved 等保持英文）；字段名、[Shot N]、At 时间戳、(Sx)、<Subject N>、任务类型前缀与 retention 标记仍为英文技术 token。AI 系统与用户提示词双侧写入语言边界；AI 输出语言不合格时（bodyLangError 校验失败，原 englishTextError），生成流程携带具体错误自动纠正最多两次（与 FL2VA 时间轴纠正同一模式）；纠正后仍不合格则按既有契约标记 invalid 并回填字段供人工修改。中文输出下说话人校验改为：取对白前最近的 (Sx)，其后发声引导以冒号结尾即通过（兼容“开口调侃：”“劝止：”等任意中文动词）；单对白自愈词表同步扩充。

## 6. 声音字段

`overall_soundscape` 使用 1–4 句（所选语言），概括环境声、物理动作声和非语言人声。不要重复对白、演唱或剧情内音乐。只有用户明确要求全片完全静音时才写 `N/A`。

`non_diegetic_music` 描述观众才能听到的配乐，包含配器、速度、节奏和动态变化；无配乐时写 `N/A`。

## 7. 自动生成路径

入口为 `enrich()`：

1. 默认勾选 AI，在模型下拉框选择模型（DeepSeek / GLM，均内置 Key）。
2. 未勾选“丰富”时，正文忠实整理为所选语言，对白同样使用所选语言；不得强制增加开场动作、停顿、手势、闭嘴状态或其他原文没有的视觉事实。
3. 勾选“丰富（AI扩写）”时，应围绕已有主体、场景、动作、表情和情绪显著丰富视觉表达，可细化既有动作过程、构图、已有元素的空间关系、可见质感和连续性；禁止新增人物、独立物体、地点、剧情事件、新动作、行为结果和对白。音景、配乐、固定镜头及画面稳定约束仅由用户显式勾选授权。
4. AI 失败或没有 Key 时，不再静默回退为可能不合规的中文离线结果。
5. 用户主动选择离线模式时，正文逐字符原样保留，不翻译、不扩写、不纠正引号或其他符号，只包装为所选模式结构。音景勾选时生成离线场景模板（模板语言与分隔符跟随「语言」选项：中文用中文模板与全角逗号，English 用英文模板与英文逗号；默认音景/配乐描述同样按语言分流），取消勾选表示全片静音（`overall_soundscape` 写 `N/A`）；配乐取消勾选时严格写 `N/A`。AI精细时间戳不作用于离线路径。复制/下载对离线结果同样执行完整 H3 校验，但均不拦截，页面不展示具体技术原因。

## 8. AI 调用

模型注册表 `MODELS`（多模型，界面 `#model` 下拉框选择；均 OpenAI 兼容 chat/completions 协议，Key 以 XOR 42 混淆内置于代码）：

| 模型 | 端点 | 模型代码 | 附加参数 |
| --- | --- | --- | --- |
| DeepSeek（DeepSeek-V4.1-Flash） | `https://api.deepseek.com/chat/completions` | `deepseek-flash` | `thinking: { type: 'disabled' }`（官方模型名；该模型默认开启思考模式，会消耗 reasoning tokens 挤占 max_tokens 预算，显式关闭以锁定非思考的确定性输出） |
| GLM（智谱 BigModel） | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-5.3-flash` | `reasoning_effort: 'low'`（GLM-5.3-Flash 与 GLM-5.3 同代，仍始终思考、不支持关闭，用 low 档控制思考开销，避免占用 max_tokens 预算） |

- `callLLM` 按 endpoint+模型代码 匹配 `MODELS` 条目并合并该条目的 `extraBody` 附加参数。
- `temperature: 0`
- `max_tokens: 6000`
- SSE 流式输出
- 超时：180 秒
- 支持主动停止并保留部分结果

实际调用只使用 `effectiveOfficialSys`、`effectiveOfficialUser`（由 `officialModeInstr`、`policySys`、`optionContract`、`req`、`officialDetailRule` 组装）。`officialSys`、`officialUser`、`modeExample` 为历史遗留的未使用字符串，仅作参考，改动时不需要同步。

`policySys` 把“不丰富”和“受限扩写”提升为互斥的 system 级策略：受限扩写要求结果在表达上明显更丰富（输入支持时约 60–140 个简洁词，所选语言；中文为等量简洁中文表达），但新增细节必须依附于既有语义，不得扩展人物、物体、事件、动作结果、动机、关系、剧情或对白。

- Ref2VA 的 `detailed_description` 以围绕既有语义充分展开为准；超过 500 词时提示检查是否加入了新人物、事件、动作或对白。
- 第一镜无时间戳；后续镜头编号连续、时间递增且不超出时长。
- T2VA、I2VA、FL2VA、L2VA 的每段对白前都必须存在合法 `(Sx)`（多人齐说可用 `(S1,S2)`）；基础模式同时检查 ID 从 S1 连续编号、多人 ID 不重复。该检查只验证确定性结构，不猜测代词或不同人物描述是否语义同一。Ref2VA 继续执行引用主体与说话人 ID 稳定性校验。
- 若四个基础模式的 AI 原始返回恰好只有一段对白，并且全文完全遗漏 `(Sx)`，规范化阶段会在该对白最近的有限发声动词前安全补充 `(S1)`；多对白结果不自动猜测人物映射，仍交由校验提示人工确认。
- 抗残音内联格式没有对白闭合符，因此校验只检查语言标签数量、标签后非空、说话人 ID 和发声动词，不再使用句末标点猜测对白终点，也不声称能够验证内联对白的完整语义边界。AI 指令要求每段内联对白独占一行、后续动作另起一行；本地无法确定边界时只提供非阻断提醒，不自动拆分或改写。
- 画外音、画外播报、旁白、广播、电话/电视/设备播放等声音必须由 AI 根据完整输入语义判断真实声源，并区分可见人物、画外人物、旁白者和设备声源。AI 在成文前应逐条清点“发声内容、声源实体、是否可见、是否允许张嘴、是否需要口型”，最终检查声源归属与闭嘴/不说话要求是否矛盾。含对白的结果会显示通用的声源核对提醒；本地不使用针对固定句式的正则替换，也不自动修改声源或说话人。
- 校验器内部仍区分错误、提醒和通过，但错误及提醒的技术原因均不在页面或复制/下载提示中展示，只写入浏览器开发者控制台供调试。生成结束后提示区保持可见：通过时显示通过状态，存在内部错误或提醒时显示不带技术诊断的中性“AI结果提示”。所有结果均保留，复制和下载不受校验影响。
- 官方严格格式中 `[Chinese]` / `[English]` 只能出现在合法 `<d>...</d>` 内；抗残音实验格式中只允许内联语言标签，不允许残留 `<d>`。标签必须与「语言」选项一致（选中文全部用 [Chinese]，选 English 全部用 [English]；选「English 正文 + 对白原文」时按每句实际语言选择，标签与台词语言不匹配即拒绝）。
- `[English]` 对白不得残留中文内容；`[Chinese]` 对白以正确标签为硬约束，并允许数字、英文缩写、专名等合法内容。
- 对白边界以 DeepSeek 的完整语义判断为准（可覆盖无提示语的直接发言）；同时用本地保守的下限交叉校验兜底——输入存在明显对白标记（引导语+冒号、或成对引号）但 AI 对白计数为 0 时判为异常，防止对白被转成动作描述（如 "calls out"）而丢失。
- `<d>` 内只允许实际说出的台词；说话引导语、说话人和语气必须使用所选语言并留在 `<d>` 外。DeepSeek 在同一次返回的内部控制行声明语义识别出的对白数量，校验器要求实际 `<d>` 块数量与之完全一致；控制行在展示前移除。
- 官方 `<d>` 格式会严格检查对白块之外是否出现任何中文（含双引号内）：出现即判定为语言漂移，不再允许比例或引号例外。该英文正文检查仅限 English 语言模式；中文模式剥离固定约束和结构 token 后逐字段、逐行检查自然语言内容（validateEnglishDescription / validateChineseDescription 由 bodyLangOk 分流）。抗残音内联格式因没有可靠结束边界，只进行保守检查，无法明确判断时降级为非阻断提醒。
- `overall_soundscape` 与 `non_diegetic_music` 开启时不得为 `N/A`；关闭时（音景关闭 = 全片静音、配乐关闭 = 无配乐）必须严格为 `N/A`。
- `overall_soundscape` 开启时必须为 1–4 句；`non_diegetic_music` 开启时必须为 1–3 句，且需覆盖配器、速度、节奏、动态四要素（关键词启发式校验）。
- 勾选“丰富（AI扩写）”时由 AI 指令要求明显丰富表达，但本地不设置强制最低字数，避免极短输入因凑长度而虚构内容；仍保留过度扩写上限。

AI 校验与表单回填相互独立。只要 AI 返回了内容，系统就保留原始输出，并将能够解析出的字段正常回填到对应文本框；校验失败只产生中性页面提示和控制台诊断，不阻断回填，也不改变其他界面逻辑。无法识别或缺失的字段不覆盖原文本框内容，便于用户直接修改。

每次生成首先调用 AI 一次；FL2VA 时间轴错误最多纠正两次，正文或对白语言错误最多纠正两次，总计最多五次调用。每次纠正携带完整原始指令与输入。纠正失败、返回为空或被停止/超时时，恢复上一份完整结果；初次请求被停止时仍保留当前部分结果。剩余错误只提示人工核对，不无限重试。完整对白清点由 AI 语义判断，本地以标签、说话人冒号结构及有限引导语作兜底。

## 12. 已知边界

- 本工具只生成提示词，不负责上传或验证真实参考素材。
- 离线模式没有翻译模型，因此中文或其他语言会原样进入描述正文；它保证字段和模式结构，不保证正文被转换为英文。
- AI 输出具有概率性；严格校验可以拒绝明显错误，但不能完全证明所有视觉语义都正确。

## 13. AI 全文翻译

生成结果区域提供独立的“AI全文翻译”弹窗，可将当前结果快照全文翻译为中文或英文。翻译不区分正文、对白、音景或配乐，但要求保留字段名、参考标签、镜头标签、说话人 ID、时间戳、时间段、`N/A`、段落顺序和 `<d>` 包装，并同步更新 `[Chinese]` / `[English]` 标签。译文只用于阅读，使用独立流式状态、中止控制和复制按钮，不修改主输出、不回填表单、不触发 H3 校验，也不影响原复制及下载功能。每次打开弹窗都会读取新快照并清空旧译文；关闭会中止并隔离旧任务，立即重开也不会被旧任务状态干扰。若翻译期间原结果变化，弹窗会提示译文基于打开时的快照；结构标识数量变化时显示人工核对提醒。

## 15. 输入提示词历史

输入历史使用浏览器 `localStorage` 保存，键名为 `h3-prompt-history-v1`，最多保留最近 30 条。每次用户点击自动生成且输入非空时保存；相同文本按完整字符串去重并更新时间顺序。历史选择只切换 `enrich_input`，不修改模式、时长、开关、结果区或各模式文本框。

历史管理提供选择、删除当前和清空全部。读取时兼容旧的纯字符串数组及当前 `{ text, updatedAt }` 结构；非法、空白或超量数据会被过滤。保存失败只写入控制台，不阻断生成。生成期间历史控件与其它输入控件一同禁用，结束后根据实际记录和当前输入恢复按钮状态。
- 不丰富 + English 对白 + 音景开启 + 配乐关闭：通过，配乐严格为 `N/A`。
- 受限扩写专项复测：`<d>` 内只包含实际台词，不包含“姥姥说：”等引导语；正文可细化既有表现，但不得新增人物、事件、新动作或对白。
- 对白识别最终调整为完全由 DeepSeek 做语义判断，本地关键词提取和补回逻辑已删除，以覆盖没有“说、说道、冒号或引号”等提示的直接对白。

测试同时发现并修复了 `normalizeFirstShot()` 在字段冒号后无空格时重复插入 `[Shot 1]` 的问题。修复后函数为幂等规范化，最终只保留一个标准首镜标签。该历史版本每次用户生成只调用一次 AI；当前有界纠正规则见 §9。
