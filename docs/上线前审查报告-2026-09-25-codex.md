## 2. 问题清单

### 严重：发布前必须处理

#### S1. 删除高级选项后，两套声音/字幕参数没有统一，生成结果在运行时被静默改写

- **位置**：`web/js/minimax_h3_integration.js:1191–1193,2383–2389,2476–2482`；交互证据：`video_nodes.py:623–625,734–741`、`prompt_tags.py:144–164,179–200`。
- **问题**：本轮删除了 `no_subtitle/soundscape/music` 的面板控件，称其已移入生成弹窗。但新控件写的是 `ai_no_subtitles/ai_soundscape/ai_music`，旧 widget 既未同步，也未停止参与执行。默认 `prompt_source=panel` 时，生成结果填入编辑器后，仍会经过 `apply_advanced_constraints`，读取旧默认值 `True/False/False`。
- **影响场景**：勾选音景和配乐，生成结果已经包含实际声音描述；运行工作流时两字段被改成 `N/A`。取消无字幕约束后，运行时也可能重新注入该约束。普通手写提示词同样失去了修改旧开关的 UI。这里是条件文本内容被改变，并不声称已验证最终视频一定无声。
- **复现**：直接调用当前 `apply_advanced_constraints`，输入 `overall_soundscape: Rain falls.`、`non_diegetic_music: Piano plays.`，使用未被新 UI 修改的旧默认值，输出两个 `N/A` 并注入无字幕约束。
- **修复建议**：明确生成选项与运行约束的语义，建立一个统一状态来源。若继续让弹窗承担原高级选项功能，必须同步两套参数并迁移旧值；若生成结果应按原文执行，则应记录来源并避免旧后处理再次覆盖。不能只删除三行控件和可见性列表。增加“弹窗生成 → 工作流执行前实际 prompt”断言。

#### S2. 旧工作流保留隐藏来源后，新编辑器结果不会成为运行输入，且无法从界面切回 panel

- **位置**：`web/js/minimax_h3_integration.js:488–492,1380–1396,2486–2496`；交互证据：`video_nodes.py:700–729`。
- **问题**：本轮移除了来源选择和 `ai_text` 编辑入口，但继续恢复/序列化 `prompt_source`。新生成动作只写编辑器及 `prompt`，未切换来源或同步 `ai_text`。当旧来源为 `ai/offline/format` 时，执行分支仍调用 `generate_prompt(ai_text, prompt_source, ...)`，覆盖已恢复的编辑器文本。
- **影响场景**：加载旧 AI 工作流，修改编辑器或点击“生成并填入”，看到新结果后运行，却再次生成旧 `ai_text`；AI 来源还会产生额外调用。旧隐藏输入为空时也可能直接报空提示词。用户没有来源入口可以纠正。
- **复现**：从 `execute` 提取提示词解析前缀，仅替换环境依赖和生成器，分别传入三个旧来源；编辑器为 `new editor result`、隐藏输入为 `old hidden idea`，三者均使用后者。
- **修复建议**：在保留旧工作流原始执行能力的同时，恢复一个可见的来源/迁移入口；至少在用户显式“生成并填入”成功后，将来源切为 `panel` 并持久化。普通编辑器编辑对于旧来源也须有明确可见的行为，不能继续表现为可编辑但执行时忽略。迁移时保留原 `ai_text` 以便回退。

### 中等：功能缺陷与边界

#### M1. “严格校验”开关对面板生成无效，非法结果仍替换编辑器并关闭弹窗

- **位置**：`web/js/minimax_h3_integration.js:2390,2460–2496,2518–2520`；对照 `video_nodes.py:727–728`。
- **问题**：开关写入 `ai_strict_validation`，但请求和 `applyGenerationResult` 都不读取它。只要 `prompt` 非空，就先填入、播放完成声音，再对 `valid=false` 弹出报告，随后关闭配置界面。注释所说“strict_validation 关闭时”没有对应条件。
- **影响场景**：默认开启严格校验时，AI 多轮纠正后仍无效的结果也被当作可填回结果处理，与工作流运行期的拒绝行为不一致。
- **复现**：执行当前 `applyGenerationResult`，隐藏严格校验为 true，传入非空 `prompt`、`valid=false`，仍观察到 `undo → apply → alert`。
- **修复建议**：在覆盖文本前检查请求发起时捕获的严格校验值；AI 严格模式失败保留原文和弹窗。关闭严格校验时才允许填回并明确提示。若离线整理允许输出待修文本，应显式定义其独立规则，而非让开关静默无效。

#### M2. 生成与润色没有双向互斥，两个响应会竞争同一编辑器

- **位置**：`web/js/minimax_h3_integration.js:2438–2442,2498–2519,2711–2732,2759`。
- **问题**：弹窗“润色”按钮检查两个标志，但 `runGeneration` 只检查 `aiGenerating`，`runPromptOptimization` 只检查 `optimizing`。润色启动后弹窗关闭，用户可重新打开配置并发起生成；自动润色入口也不检查生成状态。
- **影响场景**：润色尚未完成时启动 AI 生成/离线整理，两者都基于之前的文本发起处理，迟到响应覆盖先到结果；同时可能重复消费 API 配额。单个生成期间再点同一弹窗的润色按钮会被守卫拦住，这一方向正常。
- **复现**：执行源码中的 `runGeneration`，设置 `optimizing=true`，请求仍发送并应用结果。
- **修复建议**：在两个实际异步入口使用同一个操作锁，在任何 await 之前占用；统一禁用相关动作。响应应用前校验操作令牌和发起时的目标模式/文本版本，避免旧响应覆盖新状态。

#### M3. 收编润色按钮时删除了用户取消入口

- **位置**：`web/js/minimax_h3_integration.js:880–885,2438–2442,2671–2678,2769–2772`；差异中删除了原 `optimizePrompt.onclick` 的 `cancelOptimization()` 分支。
- **问题**：旧工具条按钮在润色中可再次点击取消。本轮删除该按钮后，弹窗“润色”在 `optimizing=true` 时直接返回，左侧计时器也没有取消事件。
- **影响场景**：误发在线润色或本地推理后，用户只能等完成/超时，或删除节点。全局运行开始时取消本地润色的自动逻辑仍在，但不能替代手动取消。
- **修复建议**：保留可见的“取消润色”按钮，或让计时区域/弹窗操作在运行中调用现有 `cancelOptimization()`，并验证客户端 abort 与服务端 cancel 都被触发。

#### M4. 新生成请求缺少取消、客户端截止时间和节点生命周期清理

- **位置**：`web/js/minimax_h3_integration.js:2409,2504,2510–2527,2532,3740–3763`；`prompt_optimizer.py:1683–1706`。
- **问题**：生成期间禁用取消并拒绝关闭遮罩；fetch 未传 AbortSignal，也没有前端计时器。`onRemoved` 只清理旧润色请求，不持有/移除新弹窗、不取消新生成、也不使其结果失效。后端直接 `to_thread`，未注册可取消任务，传给客户端和引擎的中断回调使用默认空实现。
- **影响场景**：慢请求/连接未结束时用户无法主动退出遮罩；节点被外部删除、图重载时，请求仍可能继续，完成后仍尝试写入旧节点并播放提示音。后端线程不会因为前端不再需要结果就自动停止。未实测特定 RunningHub 代理是否允许 600 秒连接，不能据此保证最长配置可用。
- **修复建议**：登记活动弹窗和生成操作；允许取消/关闭；增加前端截止时间、AbortController、节点失效令牌及结果应用守卫。后端提供线程可检查的取消信号和任务清理；若保留单请求方案，需明确断连后的执行预算与并发上限。单纯取消等待 `to_thread` 不等于终止线程。
- **排除项**：`overlay.remove()` 后 finally 访问已持有的按钮对象不会自行造成 null 解引用，不把它登记为缺陷。

#### M5. 面板与运行期 controls 仍有三项行为差异

- **位置**：`web/js/minimax_h3_integration.js:2383–2390,2454–2483`；`prompt_optimizer.py:1659–1664`；对照 `video_nodes.py:709–724`。
- **问题及影响**：
  1. `ai_visual_stability` 仍序列化，但 UI 控件被删除，`generationBody` 也未传 `visual_stability`。后端将缺省值置 false；旧工作流设置 true 时，面板生成与运行期不同。
  2. `generationMode()` 只按面板/素材推断，忽略运行期优先使用的显式 `ai_mode`。例如旧工作流 `ai_mode=l2va`、没有素材时，面板请求是 `t2va`，运行期仍是 `l2va`。
  3. 超过 15 秒时，运行期明确拒绝，但新接口将时长静默夹到 15，节点实际时长未同步。长视频用户得到的是 15 秒预算的提示词，却没有获知调整。
- **复现**：源码提取的 `generationBody` 在 `ai_visual_stability=true, ai_mode=l2va` 时输出缺少视觉稳定键、模式为 t2va；后端边界夹取行为可直接由 `_generation_payload_controls` 验证，现有测试也明确断言 999 被夹到 15。
- **修复建议**：补齐视觉稳定控件及请求映射；为两条路径共用模式解析规则，或在有提示的迁移中统一清除旧显式模式；对不支持的时长在 UI/接口一致拒绝，或明确提示并让用户选择适配，避免静默改变预算。

#### M6. 新 HTTP 出口原样返回底层异常，可包含服务端环境变量 Key

- **位置**：`prompt_optimizer.py:1705–1706,1717–1718`；调用链 `llm_client.py:39–49,64–76`、`prompt_runtime.py:32–52`。
- **问题**：新路由将 `str(error)` 直接返回。`make_client` 对 Key 仅检查 ASCII；requests 对包含换行的 Authorization 值抛出 `InvalidHeader` 时，异常文本包含整个头值。非 200 响应也把上游响应正文前 300 字附加到异常，不能保证该内容已脱敏。
- **影响场景**：服务端环境变量 Key 错误包含内部换行时，不携带 Key 的生成请求也可收到该服务端值。这里有明确配置条件，不声称正常 Key 在所有请求中都会泄露。
- **复现**：仅在测试进程临时设置虚构 `DEEPSEEK_API_KEY='audit-demo\nsecret-sentinel'`，调用新处理器，HTTP 400 的 JSON 包含 `secret-sentinel`。requests 在构造请求头时失败，无外网调用、无真实凭据读取。
- **修复建议**：新出口使用受控错误码/安全消息，对传入 Key 及实际环境变量回退 Key 做脱敏；拒绝控制字符时不要回显输入。禁止直接透传未知异常和未处理的上游正文。增加标记 Key 不得出现在 HTTP 响应/日志中的断言。
- **范围说明**：本轮登记的是新增 HTTP 响应暴露路径；历史 `ai_api_key` 明文序列化问题不在此重复上报。

### 轻微：体验/接口与测试质量

#### L1. 新接口的“非法值回退”契约与实现不符

- **位置**：`prompt_optimizer.py:1656–1664,1681`。
- **问题**：`bool('false')` 为 True；`duration='(none)'` 或非数字字符串触发 `ValueError`，不会回退；`timeout` 也有同类转换。正常新 UI 发送布尔/数字时不受影响，但手动 API 调用或脏数据表现与函数文档不一致。
- **复现**：`fixed_camera='false'` 被转换为 True；`duration='(none)'` 抛异常，由路由转为 400。
- **修复建议**：明确采用严格类型校验并返回可读 400，或使用一致的 bool/int 归一化函数实现文档承诺；避免以 Python truthiness 解析外部布尔字符串。

#### L2. 静态断言已经出现“实现不存在但测试通过”的情况

- **位置**：`tests/panel-ai-section.cjs:103–118,147–158,170–189`；对应 `web/js/minimax_h3_integration.js:1393–1395,3694–3705`。
- **问题**：测试通过 `js.includes('syncAiControls()')` 宣称 onConfigure 仍调用恢复桩，但实际只匹配到注释；本轮已删除真实调用。因为桩本来为空，这一处目前没有运行损害，却证明断言没有验证声称的行为。控件名称出现也不代表会进入请求；`indexOf(undo) < indexOf(apply)` 在前者缺失、后者存在时因 -1 仍可成立。删除旧控件的断言还会奖励 S1 所述的不完整迁移。
- **影响场景**：后续重构漏掉调用/参数/撤销时，静态测试仍可能绿灯；当前 278 条断言无法作为新交互正确性的依据。
- **修复建议**：对关键路径执行真实处理函数并观察状态/请求/调用顺序；必须保留的静态检查至少先断言两个锚点均存在，并排除注释。空恢复桩应移除误导性检查或仅测试实际需要的契约。

## 4. 测试补充建议（按价值排序，最多 5 条）

1. **从弹窗到最终运行提示词的集成测试**：对声音、音乐、无字幕分别开关，生成后直接验证 `execute` 解析后的 prompt；加入旧 ai/offline/format 工作流，检查用户显式编辑/生成后的来源及实际输入。覆盖 S1、S2。
2. **真实状态机的异步交互测试**：受控延迟两个响应，覆盖润色→生成、生成→自动润色、取消、删除节点及图切换；断言请求互斥、取消传递、迟到结果不写回、遮罩可退出。覆盖 M2–M4。
3. **UI→请求→引擎契约参数化测试**：覆盖每个布尔项 true/false、三语言、auto/显式模式、2/15/超范围时长、strict true/false 与 valid true/false；验证无效结果是否保留原文，并补真实撤销/重做的模式缓存/widget 一致性。覆盖 M1、M5、L1、L2。
4. **凭据边界测试**：跨生成/润色平台切换、同平台 Key 更新/清空、环境变量回退；用标记 Key 覆盖非法头、上游错误正文及未知异常，断言响应和允许记录的日志不含标记，并分别验证 optimizer 状态与原生 widget 的序列化策略。覆盖 M6，防止历史问题复发。
5. **测试隔离与实际 HTTP 冒烟**：用 fixture 管理 sys.modules/server/h3pkg，退出后恢复；通过 aiohttp 测试客户端校验新路由注册、非法 JSON/类型、非阻塞调度与断连行为。现有直接调用 FakeRequest 无法证明这些 HTTP 层行为。

## 5. 已验证通过项与复核边界

- 前端语法、指定 JS 脚本、全部 28 个 Python 测试通过；新增接口测试的模拟 LLM 会运行真实引擎，但没有调用真实模型服务。
- 两个新 POST 路由均已注册，generate 走 ai 分支并创建客户端，format 不创建客户端；请求体非对象会返回 400，空文本由引擎拒绝。
- 后端白名单的 mode/lang/ratio 范围与运行期所接受范围一致，model 控件存在；8 个布尔控件全部通过真实 quickjs 契约检查。
- 常规浏览器布尔值下，enrich_do_enrich/enrich_soundscape/enrich_music/auto_timestamps/fixed_camera/no_subtitles/anti_pop 的请求键与引擎匹配。没有把“存在键”当作验证了所有开关实际输出效果。
- provider 仍由原 7 项预设解析，显式 endpoint/model 覆盖、平台环境变量及 H3_LLM_API_KEY 回退仍由原 make_client 承担；不核验这些预设服务当前商业可用性。
- quickjs 执行、同步 requests 流式读取都在线程中，未发现新路由在事件循环上执行这一段阻塞工作。
- 正常串行生成的撤销快照顺序正确，填回/撤销会同步按模式缓存、prompt widget 和持久化状态。
- 恢复时的 restoringState/restoreEpoch 保护、媒体 `(none)` 清理及既有路径校验未因本轮修改移除；空 syncAiControls 本身不会抛错。
- optimizer 状态仍经 sanitizeOptimizerForWorkflow 清理密钥；它不覆盖原生 ai_api_key widget，历史限制已在表中单独说明。
- 新文案有对应中文映射；弹窗新增纵向高度限制/滚动；删除的 AI DOM 控件无遗留活动解引用。关闭后 finally 操作已持有按钮对象安全。
- 历史报告 S1–S4、M1–M16 等独立旧问题没有作为本轮新发现重列。S1/S2 是本轮入口/控件删除与旧执行链交互产生的回归；M6 是新增 HTTP 错误出口的具体暴露证据。
