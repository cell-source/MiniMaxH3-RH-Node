## H1（高）默认配置下带素材润色必然失败

**证据链**

1. `video_nodes.py:684` —— `ai_provider` 默认 `"deepseek"`（可选值 = `llm_client.PROVIDERS` 的 7 家）
2. `prompt_optimizer.py` `DEFAULT_CONFIG["read_media"] = True` → `_public_config()` → `/config`
3. 前端 `applyDialogConfig()`：`read_media` 默认勾选（`readMedia.checked = current.read_media !== false`）
4. `optimizerMediaPayload()`：`read_media !== false && spec.kind === "image"` → `item.images = [dataUrl]`
5. `_user_parts()`：`elif read_media:` → 追加 `{"type": "image_url", ...}`
6. DeepSeek 无视觉 API → 上游 400

**影响**：默认安装 + 任一参考图（首帧/尾帧/参考图）+ 点 ✦ = 必失败。失败信息是上游原文（见 M4），用户无从判断是「配置问题」。

**修复**：`prompt_optimizer.py` 新增 `_TEXT_ONLY_PROVIDERS` + `_reject_images_without_vision()`，在 `_request_parts()` 拼装后、发请求前拦截，报错文案给出可执行指引：

> 当前平台（deepseek）不支持图像理解：请在 ⚙ 配置中关闭「读取视觉素材」后重试，或改填支持视觉的模型

**边界**：仅拦截「确实携带图像分片」的请求；关闭「读取视觉素材」后按原逻辑退化为 label-only 文本（`_user_parts` 的 `else` 分支），对纯文本平台依然可用。模型名含 `vl`/`vision`/`omni` 时视为用户显式选用视觉模型，放行（避免误伤 `glm-5v-turbo` 这类）。

## H2（高）参考视频帧被静默丢弃

**证据链**

1. `optimizerMediaPayload()` 用 `optimizerSettings?.provider` 判定是否走 RunningHub 分支
2. `optimizerSettings` 来自 `/config`，其 `provider` 是 **`runninghub`**（`DEFAULT_CONFIG`）；而 RunningHub 已不在生成平台可选列表内，实际润色平台取自 `ai_provider` widget
3. 于是 `runninghub = true` → 视频走 `item.source_name = entry.name` 分支，**不产生 `images`**
4. `_user_parts()` 中 `elif read_media:` 只遍历 `item.get("images") or []` —— 空数组 → **该条目不产生任何分片**（对比：`read_media = false` 时至少还有一条 label 文本）

**影响**：勾选了「读取视觉素材」，但参考视频的内容对模型完全不可见，且无任何提示（静默降级）。

**修复**：平台判定改用 `polishProviderValue()`（生成 widget 真源），RunningHub 分支仅在用户确实是 RunningHub 平台时生效。

## M3（中）工具条徽标显示并未使用的模型

**证据**：`configuredOptimizerName()` 读 `optimizerSettings.model` / `.provider`；`applyDialogConfig()` 只写 `provider`（不写 `model`），因此 `model` 恒为 `/config` 默认的 `openai/gpt-5.6-sol`；且 `providerName` 映射表缺 `deepseek`/`glm` 键 → 落到 `|| "API"`，徽标显示 `API: GPT-5.6-sol`（首次加载则显示 `RunningHub 国内版: GPT-5.6-sol`）。

**修复**：与 H2 同根因，统一到 `polishProviderValue()` / `polishModelValue()`；映射表补 `deepseek`/`glm`。

> ⚠️ 行为变化（可回退）：未填模型时徽标由「空白」变为显示平台名（如 `DeepSeek`）。理由：空白会让人误以为未配置，而平台名是实际会被调用的东西。

**证据**：`_request_async()` → `raise RuntimeError(f"API request failed ({response.status}): {text[:1000]}")` → `optimize_prompt()` / `prompt_optimization_status()` → `web.json_response({"error": str(error)})` → 前端 `alert(data.error)`。

生成路径（`llm_client.py`）刻意用 `LLMServiceError` 剥离上游正文，润色路径与之不一致。**建议**：只回传状态码 + 自撰文案，原始正文写日志。

## L5 / L6 / L7（低）

- **L5 已修**：`PROVIDERS` 注释原写「图片部分不传（前端 label-only 回退），需要识图请改填 VL 模型名」——label-only 回退只在 `read_media = false` 时发生，与平台无关；该说明会误导后续维护。已改为指向 `_reject_images_without_vision`。
- **L6 记录**：`polishConfig.protocol` 由前端下发，会覆盖后端 `PROVIDERS` 预设的协议。当前映射正确（gemini→gemini，其余→openai），但新增平台时需同时改两处。更稳的做法是「预设优先，前端仅在 custom 时下发」。
- **L7 记录**：旧存档若 `mode: "local"`，`polishConfig.mode` 硬编码 `"api"` 会静默忽略该模式（本地视觉模型已在 UI 下线），行为可接受但无提示。
