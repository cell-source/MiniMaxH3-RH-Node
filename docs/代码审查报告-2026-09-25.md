## 🔴 严重（发布阻断项）

### S1. 路径穿越 → 恶意工作流可外传本机文件
`prompt_optimizer.py:400-410` `_resolve_input_file`：`folder_paths.get_annotated_filepath(value)` 与 `Path(input_dir)/value` 都是裸拼接，`..` 与绝对路径可逃出 input 目录。前端 `restored.media` 恢复时无文件名校验（JS :3542-3616），恶意工作流的媒体条目名可注入 `..\..\x.mp4`；当 `auto_optimize=true` 时**排队运行即自动触发**：本机 ffmpeg 解码任意视频 → 上传到工作流内置攻击者的 RunningHub 账户。
**修复**：resolve 后 `os.path.realpath` + `commonpath` 校验必须位于 input 目录内；前端恢复时拒绝含路径分隔符的名字。

### S2. 参考视频全量解码进内存 → 长 视频 OOM
`video_nodes.py:507-515`：`VideoFromFile(path).get_components()` 逐帧 append 到 EOF（已核实 comfy_api 实现），1 分钟 1080p ≈ 8.9GB，在任何降采样之前。RunningHub 受限内存 worker 上用户可直接触发。
**修复**：先探元数据（时长/分辨率），超限拒绝或按窗口裁剪解码。

### S3. 统一配置弹窗 Key 串写（已实测复现）
`minimax_h3_integration.js:2199/2406-2416/2446-2452`：优化平台与生成平台两个下拉共用一个 Key 输入框。实测复现：生成平台切 openai 填 Key → 优化平台切 deepseek → 输入框被回填成 runninghub 槽位旧 Key，刚填的 openai Key 丢弃；此刻保存则 deepseek 槽存入 RH Key。多平台用户必然踩坑，表现为莫名 401 且难排查。
**修复**：输入框记录归属平台，任一下拉切换前回存现值；删除 `|| key.value` 回退。
**附带**：清空 Key 保存时 `ai_api_key` widget 保留旧值（`if (genKey)` 分支），双状态分叉。

### S4. 后台 50ms 全局卸载模型竞态
`video_nodes.py:82-105`：AV 解码完成后 50ms `unload_all_models()` + `soft_empty_cache(force=True)`——全局操作。同 workflow 第二个模型分支或队列下一任务在 ~100ms 内开始加载时被击中 → CUDA 崩溃。
**修复**：删除该"优化"交给 ComfyUI LRU，或轮询引用计数后卸载。
